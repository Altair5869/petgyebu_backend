## R-BPFBTK: 계정 및 주요 은행 계좌 연동 ✅

**중요도**: high · **진행 상태**: todo

사용자가 회원가입 및 로그인 후 외부 금융 데이터 연동 대행사를 통해 지원되는 주요 은행을 선택하고 안전한 인증·동의 절차로 계좌를 연결할 수 있어야 한다. 서비스는 사용자가 동의한 계좌의 거래 내역 조회 권한만 사용하며, 계좌 해제·재인증·동기화 상태 확인을 제공한다. MVP에서는 대행사가 지원하는 주요 은행과 거래 내역 조회로 범위를 한정하고, 잔액 조회나 송금 기능은 포함하지 않는다.

**인수 조건**
- 사용자는 회원가입 또는 로그인 후 대행사가 지원하는 은행 목록에서 은행을 선택하고 계좌 연결을 시작할 수 있다.
- 사용자는 대행사 인증 화면에서 거래 내역 조회 권한에 동의한 후 연결할 계좌를 선택할 수 있다.
- 인증이 완료되면 연결된 계좌의 은행명, 마스킹된 계좌 번호, 마지막 동기화 시각이 표시된다.
- 새 거래 내역을 중복 없이 가져오며 수집 실패·인증 만료·지연 상태를 사용자에게 안내한다.
- 사용자는 연결된 계좌를 해제할 수 있고, 해제 이후 추가 거래 내역 동기화가 중단된다.
- 금융 인증 정보와 거래 데이터는 서비스의 보안 정책에 따라 암호화 및 접근 통제된다.

### 📌 결정 사항

| # | 항목 | 결정 |
|---|---|---|
| 1 | 금융 데이터 연동 대행사 | **코드에프(CODEF) API** — 이체 불필요, 마이데이터 직접 라이선스는 MVP 단계 자본금 요건상 불가능, 오픈뱅킹은 이체 기능이 과잉 |
| 2 | 동일 은행 복수 계좌 | **무제한 허용**. 코드에프 API가 은행 인증 1회당 전체 계좌 목록을 배열로 반환. 가계부 집계 포함/제외 토글은 F-KBBFRU에 배치 |
| 3 | 재시도 정책 | F-TEDWWF(사용자 주도 인증)는 **횟수 제한 없음** + 보안 정책 안내. F-OAVYWT(시스템 자동 동기화)는 **3회 + 지수 백오프** 유지. 통일하지 않고 성격별로 구분 |
| 4 | 연결 완료율 측정 기간 | **가입 후 24시간 이내**를 주 지표로, **7일 이내 누적**을 보조 지표로 사용 |
| 5 | 카카오뱅크·토스뱅크 지원 여부 🔄 | **v1 미지원.** 두 은행이 웹뱅킹 없는 모바일 전용 구조라 코드에프의 스크래핑 방식으로는 연동 불가. 별도 "지원 예정 안내"·"알림 신청" 기능은 넣지 않고 은행 목록에서 자연스럽게 제외. 법인 설립 완료 + 정성적 수요 신호(리뷰·CS 문의) 확인 시 금융결제원 오픈뱅킹 조회 전용 API 병행을 재검토 (근거: `04-review-log.md` "계좌 연동 전략 재검토" 2026-09-03) |

### F-TEDWWF: 은행 계좌 연결

**부모**: R-BPFBTK · **중요도**: high · **역할**: 일반 사용자(OBSOIB) · **디바이스**: 모바일, 웹

**설명**: 일반 사용자가 외부 금융 데이터 연동 대행사가 제공하는 인증 절차를 통해 지원 은행 계좌를 소비 관리용으로 연결하는 기능이다. 사용자는 거래 내역 조회 권한에 동의하고 같은 은행의 여러 계좌를 선택할 수 있으며, 연결 후 은행명·마스킹된 계좌 번호·마지막 동기화 시각을 확인한다. MVP는 대행사가 지원하는 주요 은행의 거래 내역 조회에 한정하며, 잔액 조회와 송금 기능은 포함하지 않는다.

**Rationale**: 수동 거래 입력의 부담을 줄이고 거래 내역 자동 수집의 출발점을 만들기 위해 필요하다.

**Success Criteria**: 가입 후 24시간 이내 계좌 연결 완료율 60% 이상을 달성한다. 보조 지표로 가입 후 7일 이내 누적 계좌 연결 완료율을 함께 추적한다.

| 슬롯 | 내용 |
|---|---|
| **preconditions** | - 사용자는 로그인한 상태여야 한다.<br>- 사용자는 지원 은행의 인증 수단을 보유해야 한다. |
| **trigger** | - 사용자는 계좌 연결 화면에서 지원 은행을 선택해 연결 시작 버튼을 누른다. |
| **action** 🔄 | - 서비스는 코드에프 API를 통해 선택한 은행의 인증 절차로 사용자를 이동시킨다.<br>- 인증이 성공하면 서비스는 거래 내역 조회 권한 동의와 연결할 계좌 목록(복수 선택 가능) 선택을 요청한다.<br>- 코드에프가 반환하는 해당 은행 명의의 전체 계좌 목록 중 사용자가 동의한 계좌들의 연결 정보를 각각 저장한다.<br>- 지원 은행 목록은 코드에프가 제공하는 은행 범위로 한정한다. |
| **outcome** | - 연결이 완료된 계좌의 이름 또는 식별 정보와 마지막 동기화 시각을 표시한다.<br>- 계좌 연결 완료 이벤트를 기록한다. |
| **exceptions** 🔄 | - 인증 실패 또는 취소 시 실패 사유를 안내하며, 사용자는 재시도 횟수 제한 없이 다시 시도할 수 있다.<br>- 코드에프 또는 지원 은행 측 보안 정책으로 단시간 반복 인증 시도가 차단되는 경우, 해당 안내 메시지를 그대로 노출한다.<br>- 거래 내역 동기화 실패 시 재인증을 안내한다.<br>- 대행사 또는 지원 은행에서 일시적 장애가 발생하면 연결 정보를 저장하지 않고 재시도 방법을 안내한다. |
| **display** 🔄 | - 코드에프가 지원하는 은행 목록과 연결 진행 상태를 표시한다.<br>- 연결 성공 후 은행명, 마스킹된 계좌 번호, 마지막 동기화 시각을 계좌별로 표시한다.<br>- 지원하지 않는 은행은 현재 연동을 지원하지 않는다고 안내한다. |
| **permissions** | - 일반 사용자만 자신의 계좌를 연결하거나 해제할 수 있다.<br>- 비로그인 사용자는 계좌 연결을 시작할 수 없다. |
| **rules** 🔄 | - 계좌 해제 후 해당 계좌의 추가 거래 내역 동기화를 중단한다.<br>- 금융 인증 정보와 거래 데이터는 암호화 및 접근 통제 정책을 적용한다.<br>- 서비스는 사용자가 동의한 거래 내역 조회 권한만 사용하며, 잔액 조회와 송금 권한은 요청하지 않는다.<br>- 지원 은행 목록은 코드에프가 제공하는 범위로 한정한다.<br>- 동일 은행 내 계좌 연결 개수는 제한하지 않는다. |
| **dataSpec** 🔄 | - 연결 계좌 정보는 계좌 단위로 저장하며, 각 레코드는 은행 식별자, 코드에프 연결 식별자, 마스킹된 계좌 번호, 거래 조회 동의 상태, 동의 만료 시각, 마지막 동기화 시각을 포함한다. |

## R-CCOEWW: 거래 내역 자동 수집 및 가계부 정리 ✅

**중요도**: high · **진행 상태**: todo

계좌에서 수집한 거래 내역을 수입·지출·계좌 간 이체로 구분하고 기본 카테고리를 자동 지정한다. 연결된 같은 사용자 계좌 사이의 이체는 출금과 입금을 자동으로 연결하며, 불확실한 이체 후보는 사용자가 확인하거나 직접 수정할 수 있어야 한다. 연결 또는 확인된 이체는 거래 목록에는 표시하되 총지출과 예산 사용률에서는 제외하며, 중복 거래와 취소 거래도 소비 금액에 잘못 반영되지 않도록 한다.

### 📌 결정 사항

| # | 항목 | 결정 |
|---|---|---|
| 1 | 자동 카테고리 분류 | **가맹점명 키워드 룰 테이블**만 MVP 포함. 매칭 안 되는 거래는 "미분류"로 두고 F-KBBFRU에서 수동 수정. 사용자 수정 기반 학습은 다음 버전으로 미룸 |
| 2 | 취소·환불 반영 | 원거래-환불을 **순액(net)으로 소비 지출에 반영**. 목록엔 순액만, 상세 화면에서 연결 관계 확인 |
| 3 | 이체 후보 매칭 기준 | **금액 완전 일치 + 발생 시각 차이 10분 이내 + 연결된 계좌 쌍 사이에서만** 자동 연결 |
| 4 | 90일 초기 수집 범위 | 코드에프 최대 12개월 지원, 호환 문제 없음. **페이지 단위 순차 호출로 90일치 전체 수집 필요**(단일 호출로 안 채워질 수 있음) |
| 5 | 가계부 제외 계좌 표시 | 목록에는 "집계 제외" 뱃지(기본값). 설정 페이지에서 계좌별 **"완전히 숨김"** 옵션도 선택 가능 |

### F-OAVYWT: 거래 내역 자동 동기화

**부모**: R-CCOEWW · **중요도**: high · **역할**: 일반 사용자(OBSOIB) · **디바이스**: 모바일, 웹

**설명**: 일반 사용자가 외부 금융 데이터 연동 대행사를 통해 연결한 지원 은행 계좌의 거래 내역을 서비스가 자동으로 수집하고 최신 상태로 동기화하는 기능이다. 서비스는 유효한 거래 조회 동의가 있는 계좌에서 대행사가 제공하는 거래 조회 범위 내의 신규 거래만 가져오며, 같은 사용자 계좌 사이의 이체 후보도 감지한다. 이 기능은 계좌 연결 자체와 거래의 상세 분류·수정 기능은 포함하지 않는다.

**Rationale**: 은행별 연결 방식을 직접 관리하지 않고도 지원 은행의 거래 내역을 안정적으로 수집해야 수동 입력 부담을 줄이고 소비 현황의 신뢰도를 유지할 수 있다.

**Success Criteria**: 지원 은행에서 유효한 거래 조회 동의를 유지한 연결 계좌를 기준으로 예정된 동기화 시도의 95% 이상을 정상 완료한다.

| 슬롯 | 내용 |
|---|---|
| **preconditions** | - 사용자는 로그인한 상태여야 한다.<br>- 사용자는 대행사를 통해 거래 내역 조회 권한이 유효한 지원 은행 계좌를 하나 이상 연결해야 한다. |
| **trigger** | - 서비스는 연결된 계좌의 거래 내역을 동기화 일정 또는 사용자의 새로고침 요청에 따라 수집한다.<br>- 서비스는 하루에 여러 차례 거래 내역 동기화를 시도한다. |
| **action** 🔄 | - 서비스는 외부 금융 데이터 연동 대행사를 통해 연결 계좌에서 조회 가능한 기간의 신규 거래 내역을 가져온다.<br>- 서비스는 거래 식별 정보와 거래 일시, 금액, 거래처를 기준으로 중복 거래를 식별한다.<br>- 서비스는 같은 사용자가 연결한 계좌의 출금 거래와 입금 거래를 비교해 이체 후보를 감지한다.<br>- 명확하게 일치하는 이체 후보는 하나의 계좌 간 이체 쌍으로 연결하고, 불확실한 후보는 사용자 확인 대상으로 저장한다.<br>- 서비스는 새 거래만 가계부 거래 목록에 저장하고 마지막 동기화 시각을 갱신한다.<br>- 최초 연결 시 최근 90일의 거래 내역을 가져온다.<br>- 백그라운드 정기 동기화는 하루 2회(오전 9시, 오후 9시)로 시작한다.<br>- 앱 진입 시 수동 동기화는 마지막 동기화 후 1시간 경과 시에만 재호출을 허용하고, 그 안에는 캐시를 사용한다.<br>- 사용자가 "새로고침" 버튼을 명시적으로 눌렀을 때는 캐시를 무시하고 즉시 호출하되, 남용 방지를 위해 분당 1회로 제한한다.<br>- **서비스는 미리 정의된 가맹점명 키워드 룰 테이블을 기준으로 거래에 기본 카테고리를 자동 지정하며, 매칭되지 않는 거래는 미분류로 남긴다.**<br>- **최초 연결 시 90일치 수집은 페이지 단위로 순차 호출하여 전체 기간을 채운다. 단일 호출로 전체 기간이 반환되지 않을 수 있음을 전제로 구현한다.**<br>- **서비스는 원거래와 환불 거래를 원거래 참조 식별자를 기준으로 연결하고, 순액을 소비 지출 계산에 반영한다.** |

### F-VZFPVW: 예산 사용률 연동 반려동물 소비 피드백

**부모**: R-ENPLNB · **중요도**: high · **역할**: 일반 사용자(OBSOIB) · **디바이스**: 모바일, 웹

**설명**: 일반 사용자가 메인 화면에서 선택한 반려동물의 행동·표정·상태 묘사 문구를 통해 현재 예산 소비 상태를 즉시 이해하도록 하는 기능이다. 서비스는 계좌 간 이체를 제외한 활성 예산의 소비 지출과 유효하게 저장된 상태 구간을 바탕으로 하나의 캐릭터 상태만 선택하고, 사용률·남은 예산 또는 초과 금액을 함께 제공한다. MVP는 소비 상태 안내와 상태 설명에 집중하며, 실제 금융 조언이나 사용자의 지출을 제한하는 기능은 포함하지 않는다.

**Rationale**: 예산 사용률마다 하나의 명확한 캐릭터 상태를 보여야 사용자가 소비 상태를 혼동 없이 이해할 수 있다.

| 슬롯 | 내용 |
|---|---|
| **preconditions** | - 사용자는 반려동물 캐릭터를 선택해야 한다.<br>- 사용자는 활성 예산 기간과 목표 예산을 설정해야 한다.<br>- 예산 계산에 반영할 거래 내역이 존재하거나 동기화 상태를 확인할 수 있어야 한다. |

| **dataSpec** 🔄 | - 활성 예산의 사용률, 남은 예산 또는 초과 금액, 적용된 상태 구간을 소비 피드백 표시용으로 조회한다.<br>- 사용자별 선택 캐릭터 유형과 사용자 설정 임계값을 상태 계산에 사용한다.<br>- **상태별 묘사 문구는 캐릭터 유형과 무관하게 상태 6단계에 공통 적용되며, 별도 콘텐츠 테이블로 관리한다(위 R-ENPLNB 결정 사항의 문구표 참고).** |

### F-TKSQSR: 핵심 소비 요약 확인

**부모**: R-ZHBMMB · **중요도**: medium · **역할**: 일반 사용자(OBSOIB) · **디바이스**: 모바일, 웹

**설명**: 일반 사용자가 앱을 열었을 때 현재 활성 예산 기간의 핵심 소비 현황을 한눈에 확인하는 기능이다. 총 지출, 예산 사용률, 남은 예산 또는 초과 금액과 주요 지출 카테고리를 우선 제공하며, 사용자가 복잡한 그래프를 해석하지 않아도 소비 상태를 판단하도록 돕는다. 반려동물의 감정·행동 표현 자체는 별도 반려동물 소비 피드백 기능의 범위로 두고, 이 기능은 이를 뒷받침하는 정확한 소비 요약 수치에 집중한다.

| 슬롯 | 내용 |
|---|---|
| **preconditions** | - 사용자는 로그인한 상태여야 한다.<br>- 사용자는 활성 예산 기간을 설정했거나 소비 요약을 조회할 기간을 선택할 수 있어야 한다.<br>- 거래 내역 수집 또는 동기화 상태를 확인할 수 있어야 한다. |
| **trigger** | - 사용자는 앱을 실행하거나 소비 요약 화면으로 이동한다.<br>- 사용자는 조회할 예산 기간 또는 분석 기간을 선택할 수 있다. |
| **action** | - 서비스는 선택한 기간의 수집된 거래 내역을 집계한다.<br>- 서비스는 총 지출, 예산 사용률, 남은 예산 또는 초과 금액을 계산해 요약으로 제공한다.<br>- 서비스는 지출 금액이 큰 주요 카테고리를 함께 제공한다. |
| **outcome** | - 사용자는 선택한 기간의 핵심 소비 현황을 첫 화면에서 확인할 수 있다.<br>- 사용자는 필요 시 카테고리별 또는 기간별 상세 분석 화면으로 이동할 수 있다.<br>- 소비 요약 조회 이벤트를 기록한다. |
| **exceptions** | - 거래 내역이 없거나 분석 데이터가 부족하면 빈 상태와 거래 내역 확인 방법을 안내한다.<br>- 거래 내역 동기화가 진행 중이거나 지연되면 최신 반영 시각과 현재 동기화 상태를 안내한다. |
| **display** 🔄 | - 요약 화면에는 선택한 기간, 총 지출, 예산 사용률, 남은 예산 또는 초과 금액을 표시한다.<br>- **주요 지출 카테고리는 지출 금액 기준 상위 3개만 표시하며, 3개 미만인 경우 있는 만큼만 표시한다. 동률이면 최근 거래가 있는 카테고리를 우선한다.**<br>- **직전 예산 기간 대비 지출 증감률을 "지난달보다 N% 더/덜 썼어요" 형식으로 한 줄 표시한다. 비교 대상 기간이 없는 신규 사용자는 이 줄을 표시하지 않는다.**<br>- 표시되는 요약 수치의 기준이 되는 거래 내역 반영 시각을 표시한다. |
| **permissions** | - 일반 사용자는 자신의 거래 내역과 예산 데이터를 기반으로 한 소비 요약만 조회할 수 있다.<br>- 비로그인 사용자는 소비 요약을 조회할 수 없다. |
| **rules** 🔄 | - 총 지출과 카테고리별 지출 합계는 거래 상세 내역의 확정된 지출 거래를 기준으로 계산한다.<br>- 수입 거래는 기본적으로 총 지출과 카테고리별 지출 계산에서 제외한다.<br>- 취소 또는 환불 거래의 반영 기준은 거래 내역 자동 수집 및 가계부 정리 정책을 따른다.<br>- 활성 예산이 있는 경우 예산 사용률과 남은 예산 또는 초과 금액은 해당 예산 설정 기준을 따른다.<br>- **가계부 집계에서 제외된 계좌의 거래는 총 지출, 카테고리별 지출 집계에서 제외한다. 단, "완전히 숨김"으로 설정하지 않은 경우 거래 목록에서는 여전히 조회 가능하다.** |
| **dataSpec** 🔄 | - 소비 요약 데이터는 사용자 ID, 조회 기간, 총 지출, 예산 금액, 예산 사용률, 남은 예산 또는 초과 금액, 카테고리별 지출 집계, 마지막 동기화 시각, **직전 기간 대비 증감률**로 구성한다.<br>- 카테고리별 집계 데이터는 카테고리 ID, 카테고리명, 지출 금액, 지출 비중을 포함한다. |

### F-IWBASY: 카테고리 및 기간별 소비 분석

**부모**: R-ZHBMMB · **중요도**: medium · **역할**: 일반 사용자(OBSOIB) · **디바이스**: 모바일, 웹

**설명**: 일반 사용자가 요약 화면에서 필요할 때 카테고리별 지출 구성과 기간별 지출 추이를 상세히 확인하는 기능이다. 사용자는 분석 기간을 선택하고 카테고리별 금액·비중 및 주간 또는 월간 지출 합계를 확인해 소비가 집중된 영역과 변화 추이를 파악할 수 있다. MVP는 소비 인지와 행동 판단에 필요한 집계와 상세 거래 이동을 제공하며, 복잡한 예측 분석이나 투자 분석은 포함하지 않는다.

| 슬롯 | 내용 |
|---|---|
| **preconditions** | - 사용자는 로그인한 상태여야 한다.<br>- 선택한 분석 기간에 거래 내역이 수집되어 있어야 한다. |
| **trigger** | - 사용자는 소비 요약 화면에서 카테고리별 분석 또는 기간별 분석을 선택한다.<br>- 사용자는 분석에 적용할 기간을 선택하거나 변경한다. |
| **action** 🔄 | - 서비스는 선택한 기간의 지출 거래를 카테고리별로 집계한다.<br>- 서비스는 선택한 단위에 따라 기간별 지출 합계를 집계한다.<br>- 사용자는 특정 카테고리 또는 기간 구간을 선택해 해당 거래 상세 내역으로 이동할 수 있다.<br>- **서비스는 조회 기간이 8주 이하이면 주간 단위, 8주를 초과하면 월간 단위로 자동 전환하여 집계한다.** |
| **outcome** | - 사용자는 카테고리별 지출 금액과 비중을 비교할 수 있다.<br>- 사용자는 선택한 기간의 주간 또는 월간 지출 합계를 확인할 수 있다.<br>- 사용자는 분석 수치와 연결된 거래 상세 내역을 확인할 수 있다. |
| **exceptions** | - 선택한 기간에 지출 거래가 없으면 분석할 소비 내역이 없음을 안내한다.<br>- 특정 카테고리에 분류된 거래가 없으면 해당 카테고리의 지출이 없음을 표시한다. |
| **display** | - 카테고리별 분석에는 카테고리명, 지출 금액, 전체 지출 대비 비중을 표시한다.<br>- 기간별 분석에는 각 집계 기간과 해당 기간의 지출 합계를 표시한다.<br>- 사용자가 선택한 분석 기간과 적용된 집계 단위를 화면에 표시한다. |
| **permissions** | - 일반 사용자는 자신의 거래 데이터를 기반으로 한 카테고리별 및 기간별 분석만 조회할 수 있다.<br>- 비로그인 사용자는 소비 분석을 조회할 수 없다. |
| **rules** 🔄 | - 카테고리별 지출 금액의 합계는 동일 기간의 총 지출과 일치해야 한다.<br>- 기간별 지출 합계의 총합은 동일 기간의 총 지출과 일치해야 한다.<br>- 사용자가 거래의 카테고리 또는 수입·지출 구분을 수정하면 관련 분석 집계에 반영한다.<br>- 수입 거래는 기본적으로 지출 분석 집계에서 제외한다.<br>- **가계부 집계에서 제외된 계좌의 거래는 기간별·카테고리별 지출 집계에서 제외한다. 단, "완전히 숨김"으로 설정하지 않은 경우 거래 목록에서는 여전히 조회 가능하다.** |
| **dataSpec** | - 카테고리 분석 데이터는 사용자 ID, 분석 기간, 카테고리 ID, 카테고리명, 지출 금액, 지출 비중으로 구성한다.<br>- 기간별 분석 데이터는 사용자 ID, 분석 기간, 집계 단위, 각 구간의 시작일과 종료일, 지출 합계로 구성한다.<br>- 분석 상세 이동을 위해 각 집계 항목은 연결된 거래 조회 조건을 포함한다. |

## R-VLQYRM: 절약 칭찬 및 수집형 보상 ✅

**중요도**: medium · **진행 상태**: todo

사용자가 예산을 지키거나 이전 기간보다 소비를 줄이면 반려동물이 칭찬 반응을 보이고 크레딧(인앱 화폐)을 지급받는다. 사용자는 크레딧으로 상점에서 파트너 꾸미기 아이템을 구매할 수 있다.

### F-EZZFNU: 절약 조건 판정 및 크레딧 보상 지급

**부모**: R-VLQYRM · **중요도**: medium · **역할**: 일반 사용자(OBSOIB) · **디바이스**: 모바일, 웹

**설명** 🔄: 일반 사용자가 활성 예산 기간에서 정의된 절약 조건을 충족했을 때, 서비스가 예산 상태와 이전 기간 대비 지출을 판정하여 반려동물의 칭찬 반응과 크레딧(인앱 화폐)을 지급하는 기능이다. 사용자는 지급받은 크레딧으로 F-HPWCNJ 상점에서 파트너 꾸미기 아이템을 구매할 수 있다. 동일 조건으로 보상이 중복 지급되지 않으며, 크레딧은 실제 화폐로 교환하거나 구매할 수 없다. MVP는 현금성 혜택이나 복잡한 게임 경제 없이 소비 관리 참여를 강화하는 디지털 보상 지급에 한정한다.

| 슬롯 | 내용 |
|---|---|
| **preconditions** | - 사용자는 로그인한 상태여야 한다.<br>- 사용자는 활성 예산 기간과 목표 예산을 설정해야 한다.<br>- 절약 조건을 판정할 거래 내역이 수집되고 예산 계산에 반영되어야 한다. |
| **trigger** | - 활성 예산 기간이 종료되거나 사전에 정의된 절약 조건이 충족되면 보상 판정을 시작한다. |
| **action** 🔄 | - **서비스는 예산 기간 시작 시점에 저장해둔 목표 금액을 기준으로 "목표 예산 이내 지출" 조건 충족 여부를 판정한다.**<br>- **서비스는 직전 1개 예산 기간 지출 합계 대비 이번 기간 지출 합계가 10% 이상 감소했는지로 "이전 기간 대비 절약" 조건 충족 여부를 판정한다.**<br>- **조건을 충족하면 반려동물의 칭찬 반응을 표시하고 조건별로 정해진 크레딧을 지급한다(목표 이내 지출 100 크레딧, 이전 대비 10% 이상 절약 200 크레딧, 두 조건 모두 충족 시 합산 지급).**<br>- 서비스는 보상 지급 내역과 보상 지급 이벤트를 기록한다.<br>- **절약 보상 판정은 예산 기간 종료 → 다음 기간 자동 생성 → 반려동물 상태 재계산이 끝난 뒤에 실행하고, 그 다음에 보상 알림을 표시한다.** |
| **outcome** 🔄 | - **사용자는 획득한 크레딧과 지급 사유를 확인할 수 있다.**<br>- 동일한 보상 조건으로는 사용자에게 보상을 한 번만 지급한다.<br>- **지급된 크레딧은 F-HPWCNJ 상점에서 사용 가능한 잔액에 즉시 반영된다.** |
| **exceptions** 🔄 | - 기간 종료 후 거래 데이터가 변경되어도 이미 지급된 보상은 유지한다.<br>- **첫 예산 기간은 비교할 직전 기간이 없으므로 "이전 기간 대비 절약" 조건은 평가하지 않는다.** |
| **display** 🔄 | - 보상 획득 시 반려동물의 칭찬 행동 또는 표정과 축하 메시지를 표시한다.<br>- **보상 안내에는 지급된 크레딧 수량과 지급 사유(조건명)를 표시한다.** |
| **permissions** | - 일반 사용자는 자신의 보상 지급 결과와 지급 내역만 확인할 수 있다.<br>- 비로그인 사용자는 보상 지급 결과를 확인할 수 없다. |
| **rules** 🔄 | - **보상은 실제 금융 혜택이나 현금성 가치가 없는 크레딧(인앱 화폐)으로 제공하며, 크레딧은 실제 화폐로 구매하거나 환전할 수 없다.**<br>- 보상 표현은 소비를 과도하게 줄이도록 압박하지 않고 긍정적 피드백을 우선한다.<br>- **"목표 예산 이내 지출" 조건은 예산 기간 시작 시점에 저장된 목표 금액을 기준으로 판정하며, 기간 중 목표 금액이 변경되어도 이 판정 기준은 소급 변경하지 않는다.**<br>- **"이전 기간 대비 절약" 조건은 바로 직전 1개 예산 기간과만 비교하며, 지출이 10% 이상 감소한 경우에만 충족한다.**<br>- 보상은 예산 기간 종료 후, 다음 기간이 자동 생성되고 반려동물 상태가 재계산된 이후에 최종 판정하여 지급한다. |
| **dataSpec** 🔄 | - **보상 지급 기록에는 사용자 식별자, 보상 식별자, 지급 크레딧 수량, 지급 조건, 판정 기간, 지급 시각, 지급 상태를 저장한다.**<br>- **절약 조건 판정에는 예산 기간, 기간 시작 시점 목표 금액 스냅샷, 기간 지출 합계, 예산 사용률, 직전 기간 지출 합계를 사용한다.**<br>- **사용자별 보유 크레딧 잔액을 별도로 저장하고, 지급·차감(구매) 시마다 갱신한다.** |

### F-HPWCNJ: 보상 보관함 및 상점

**부모**: R-VLQYRM · **중요도**: medium · **역할**: 일반 사용자(OBSOIB) · **디바이스**: 모바일, 웹

**설명** 🔄: 일반 사용자가 지급받은 크레딧 잔액과 구매한 꾸미기 아이템을 확인하고, 크레딧으로 파트너 꾸미기 아이템을 구매하는 기능이다. 보관함은 보유 크레딧, 구매 가능한 아이템 목록(상점), 이미 구매해 보유 중인 아이템 목록을 함께 제공한다. MVP는 아이템 구매와 보유 현황 확인에 집중하며, 아이템 재판매·사용자 간 교환·크레딧의 현금 전환은 포함하지 않는다.

| 슬롯 | 내용 |
|---|---|
| **preconditions** | - 사용자는 로그인한 상태여야 한다.<br>- 사용자는 하나 이상의 보상을 지급받았거나 보관함에 접근할 수 있어야 한다. |
| **trigger** | - 사용자는 보상 획득 안내 또는 메뉴에서 보관함을 연다. |
| **action** 🔄 | - 서비스는 사용자의 보상 지급 기록을 조회해 보유 크레딧 잔액을 계산한다.<br>- **사용자는 상점에서 구매 가능한 아이템 목록을 확인하고, 보유 크레딧으로 아이템을 구매할 수 있다.**<br>- 사용자는 개별 보유 아이템을 선택해 획득 시점과 지급/구매 사유를 확인한다. |
| **outcome** 🔄 | - 사용자는 자신이 보유한 크레딧 잔액과 구매한 아이템의 수집 현황을 확인할 수 있다.<br>- 사용자는 각 아이템의 가격(크레딧)과 획득 경로(구매/지급)를 확인할 수 있다.<br>- **아이템 구매가 완료되면 보유 크레딧 잔액에서 아이템 가격만큼 즉시 차감된다.** |
| **exceptions** 🔄 | - 획득한 보상이 없으면 보관함의 빈 상태와 보상 획득 방법을 안내한다.<br>- **보유 크레딧이 아이템 가격보다 적으면 구매를 막고 부족한 크레딧 수량을 안내한다.** |
| **display** 🔄 | - **상점 화면 상단에 보유 크레딧 잔액을 표시한다.**<br>- **상점의 각 아이템에는 이름, 이미지, 필요 크레딧 가격을 표시한다(가격대는 100~500 크레딧).**<br>- 보관함에는 구매 완료된 아이템의 이미지, 이름, 획득 일시를 표시한다. |
| **permissions** | - 일반 사용자는 자신의 보관함과 보상 내역만 조회할 수 있다.<br>- 다른 사용자의 보관함과 보상 내역은 조회할 수 없다. |
| **rules** 🔄 | - 보관함의 아이템은 구매 및 지급 기록을 기준으로 표시한다.<br>- 아이템은 재판매, 사용자 간 교환 또는 현금성 혜택으로 전환할 수 없다.<br>- **크레딧은 실제 화폐로 구매하거나 환전할 수 없으며, 오직 F-EZZFNU의 절약 보상으로만 획득 가능하다.**<br>- **아이템 가격은 100~500 크레딧 범위에서 등급별로 구성한다.** |
| **dataSpec** 🔄 | - **아이템(상점) 항목에는 아이템 식별자, 이름, 유형, 이미지 정보, 필요 크레딧 가격, 설명을 저장한다.**<br>- **아이템 보유 기록에는 사용자 식별자, 아이템 식별자, 획득 경로(구매/지급), 획득 시각을 저장한다.**<br>- **사용자별 보유 크레딧 잔액은 F-EZZFNU와 공유하는 단일 잔액 필드로 관리한다.** |
